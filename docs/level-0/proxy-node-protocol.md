# 代理、节点、协议到底是什么？

这三个词经常一起出现，也是新手最容易混淆的三个概念。

先分别理解。

## 什么是代理？

最简单的理解：

> **代理就是帮你转发网络请求。**

正常情况下：

```text
你的设备
   ↓
  目标
```

使用代理后：

```text
 你的设备
   ↓
代理服务器
   ↓
  目标
  ```

代理服务器站在中间，帮你转发请求。

---

## 什么是节点？

“节点”可以简单理解成：

> **一个代理服务器。**

比如你看到：

```text
日本节点
香港节点
美国节点
```

这里的“节点”，通常就是指一个个**代理服务器**。

一个节点通常会包含一些用于建立连接的信息，例如：

```text
服务器地址
端口
使用的协议
认证信息
TLS 等连接参数
```

例如：

```yaml
proxies:
  - name: Japan
    type: vless
    server: example.com
    port: 443
```

这里的 `Japan` 就可以理解成一个节点。

它告诉 Mihomo：

> **有这么一个代理服务器，可以按照这里的参数去连接。**

所以，对于初学者来说，可以先这样理解：

```text
节点=一个具体的代理连接
```

而：

```text
协议=这个连接使用什么方式进行通信

代理服务器=这个从客户端发出的网站连接要连接到哪里

端口=从服务器的哪个端口连接
```

---

## 什么是协议？

协议可以理解成：

> **双方约定好的通信方式。**

就像人与人交流需要使用双方都懂的语言。

代理通信也有不同的协议，例如：

```text
VLESS
Trojan
Shadowsocks
Hysteria2
```

它们规定了通信应该如何进行。

所以：

```text
        协议
         ↓
     “怎么说话”

       节点
        ↓
“跟谁说话，以及怎么找到他”
```

---

## 把三个概念放在一起

假设：

```text
协议：VLESS
服务器：example.com
端口：443
```

它们组合起来，才形成一个可以交给 Mihomo 使用的具体代理配置。

例如：

```yaml
proxies:
  - name: Japan
    type: vless
    server: example.com
    port: 443
```

这里暂时不用纠结每个字段。

你只需要知道：

```text
name
↓
给这个节点取名字

type
↓
使用什么协议

server
↓
服务器在哪里

port
↓
服务器的哪个端口
```

看到这里，你已经可以开始“读懂”最简单的 Mihomo 配置了。
